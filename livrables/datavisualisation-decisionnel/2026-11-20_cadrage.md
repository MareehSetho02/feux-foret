**Problématique** : quel seuil d'un indice de risque, calculé par zone à partir de facteurs naturels et humains, permettrait au SDIS 33 de déclencher son dispositif renforcé à l'été 2027 de façon efficiente, tout en limitant les fausses alertes ?

**Emprise** : Gironde (33), avec les Landes (40) et le Lot-et-Garonne (47) en comparaison. Grain : carreau DFCI de 2 km pour les facteurs, commune × jour pour l'évaluation du seuil.

Ces données ne sont pas publiques ; elles amélioreraient fortement l'évaluation du seuil ([liste complète](../../docs/sources/indicateurs-x-donnees.md#6-données-à-demander-au-sdis-33-et-aux-partenaires)) :

3. Registre des déclenchements du dispositif renforcé et seuil actuellement appliqué (SDIS 33).

## 2. Stack technique

| Étape | Outil | Pourquoi |
| --- | --- | --- |
| Langage | **Python 3.12** | Un seul langage pour l'extraction, les transformations et le tableau de bord ; déjà utilisé par nos scripts. |
| Extraction (Bronze) | Scripts Python (`requests`) et téléchargements data.gouv, stockés tels quels dans `data/raw/` | Garde une copie brute de chaque source ; la provenance est tenue dans [`data/README.md`](../../data/README.md). |
| Stockage des couches Silver et Gold | **Fichiers Parquet** | Format colonnes compressé, typé, lisible par tous les outils Python. |
| Entrepôt | **DuckDB**, avec l'extension `spatial` | Base analytique dans un simple fichier, sans serveur à administrer. Elle traite sans difficulté les ≈ 15 millions de lignes carreau × jour et gère les géométries (reprojection en Lambert 93, intersections carreau × commune). |
| Transformations | SQL DuckDB, appelé depuis des scripts Python | Règles de nettoyage et d'alignement lisibles et versionnées dans `scripts/transform/`. |
| Qualité | Contrôles SQL à chaque passage de couche (clés uniques, valeurs vides, codes inconnus du COG) | Rend visibles les problèmes relevés dans le [modèle de données](../modelisation-pipeline-donnee/2026-11-20_modele-donnees.md#3-alignement-des-données-qui-se-chevauchent). |
| Tableau de bord | **Streamlit** (Python), avec des cartes interactives | Lit directement l'entrepôt DuckDB. Permet de comparer les seuils testés sur une carte des carreaux et des communes. Le code est versionné dans le dépôt et l'outil est gratuit sur tous les systèmes. |
| Documentation | Markdown et diagrammes **Mermaid** dans le dépôt | Affichés directement sur GitHub et relus en pull request. |
| Versionnement | Git et GitHub : une branche par livrable, Conventional Commits, pull requests relues | Conventions décrites dans le [README](../../README.md#conventions). |

**Alternatives écartées** :
- **PostgreSQL + PostGIS** : très bon pour le spatial, mais il faut un serveur à installer et à administrer, sans gain pour un volume de cette taille.
- **Power BI** : rapide à prendre en main, mais réservé à Windows, limité pour afficher des milliers de polygones, et son fichier `.pbix` se versionne mal.
